Async `migrate --apply` no longer journals a step as failed when the submit request fails
with a transport error (e.g. a gateway 524) before any poll saw the query running (#671): the
server may be running the query unobserved, so the step now polls through the same bounded
grace, and stays `started` for a re-run to re-attach if no trace appears. A server rejection
still fails at once - the ObsessionDB console executor now keeps ClickHouse's exception code
from the server's error text so a rejection is told from a transport error.
