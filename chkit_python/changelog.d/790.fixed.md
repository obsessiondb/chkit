An async `chkit migrate --apply` statement now runs with `async_insert = 0`, as sync statements already did, and every migration write also waits for an asynchronous insert's flush (`wait_for_async_insert = 1`), so an `INSERT … VALUES` is no longer recorded as applied while its rows are still buffered. `migrate --setting` refuses `async_insert=1`, `wait_for_async_insert=0` and `profile` before anything runs.
