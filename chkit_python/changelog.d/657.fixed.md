Async `migrate --apply` no longer journals a completed load as failed when a proxy cuts the
submit request (e.g. HTTP 524) while the server keeps running the query (#657). An
indeterminate submit error now polls through a bounded grace so `system.query_log` can catch
up; if the query never appears server-side, the attempt stays `started` and the error asks to
re-run `chkit migrate --apply` to re-attach, instead of recording the load as failed. A
definitive server rejection (a ClickHouse exception code, an authentication failure) still
fails right away.
