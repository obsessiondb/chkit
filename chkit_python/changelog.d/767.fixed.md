A re-run of `chkit migrate --apply` runs an async statement again, or its `-- before-retry:` SQL, only when the server rejected the attempt before it started: every attempt runs under a random query id recorded in the journal first and sent once, and a statement whose outcome cannot be told stops with `async_outcome_unknown`. Add the journal's `operation_fingerprints` column with a user that can alter it before running async statements.
