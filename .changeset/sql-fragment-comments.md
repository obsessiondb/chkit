Remove SQL comments from schema SQL fragments before writing them on one line (#232). A `--`, `//` or `#` comment in a view or materialized view `as`, `partitionBy`, `ttl`, a skip index expression, a projection, or a dictionary `source`/`layout`/`lifetime` lost the newline that ended it, so it swallowed the rest of the fragment, and a trailing one swallowed the statement's `;`: `chkit generate` accepted the schema, then `chkit migrate` failed with a syntax error after earlier statements had run, or created a truncated view. Comments now follow ClickHouse's syntax (`--`, `//`, `#!`, `# ` and nested `/* */`), and comment markers inside string literals and quoted identifiers are kept. Full-text (`type: 'text'`) index expressions keep their own parser, which only drops `--` and non-nested `/* */` comments. Fragments without comments normalize exactly as before, so existing snapshots plan nothing new, except an object whose snapshot already holds SQL cut short by a comment: the next `chkit generate` recreates it in full. A `ttl` or `partitionBy` that holds only comments counts as no clause, so removing a TTL that way renders `REMOVE TTL` instead of an invalid `MODIFY TTL ;`. `chkit drift` no longer reports comments in TTL, partition, skip index or projection SQL as drift, and still compares literal defaults such as `'http://x'` as values. `mv_replay` backfills of a materialized view with commented SQL replay the full query. `normalizeSQLFragment` from `@chkit/core` now removes comments; pass it SQL only. Upgrade every chkit install in a team together: snapshots written by this version hold SQL without comments, so an older chkit plans to recreate or alter every object whose definition carries a comment.
