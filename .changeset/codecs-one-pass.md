Column codecs follow ClickHouse's rules and stored forms (#465).

**After upgrading, `generate` plans a codec change for every `Delta` or `Gorilla` column written without `size`.** chkit used to render a bare `Delta` as `Delta(1)` and a bare `Gorilla` as `Gorilla(1)`, and stored `size: 1` in the snapshot. One byte is the wrong width for anything but 8-bit columns: on 5M rows, `Delta(1), ZSTD(1)` compressed a `UInt64` column 2.42× against 4.77× for `Delta(8), ZSTD(1)`, a `DateTime` column 5.91× against 30.57× for `Delta(4)`, and `Gorilla(1)` made a `Float64` column larger (0.88×, against 8.52× for `Gorilla(8)`). chkit now renders them bare (`CODEC(Delta, ZSTD(1))`) and ClickHouse fills in the column's value width, so the next `generate` plans one `MODIFY COLUMN ... CODEC(...)` per such column; between that `generate` and the migration, `drift` reports the column. The change runs no mutation: parts written after it use the new codec, and existing parts keep theirs until ClickHouse merges them (run `OPTIMIZE TABLE ... FINAL` yourself to recompress them now). A column whose schema sets `size: 1` is unchanged.

- Removing a codec always uses `MODIFY COLUMN ... REMOVE CODEC`. When the type, default or comment changes too, `REMOVE CODEC` is its own operation before the `MODIFY COLUMN`; before, a single `MODIFY COLUMN` without a codec kept the stored one and drift reported the column forever.
- `generate` reports the codecs ClickHouse rejects instead of failing the migration partway, with new issue codes: `codec_unknown` (a missing or unknown `kind`; kinds are case-sensitive), `codec_parameter_invalid` (unknown fields and out-of-range parameters such as `ZSTD` level 23, `FPC` level 0, `Delta` size 3 or a level of 1.5, which used to render broken SQL such as `CODEC()` or `FPC(undefined, undefined)`), `codec_none_combined`, `codec_chain_encryption_not_last`, `codec_chain_no_compression` (a chain of only `Delta`/`GCD`, before `codec_chain_must_end_with_general`), `codec_chain_float_order` (`Gorilla`/`FPC`/`ALP` after `Delta`/`DoubleDelta`, and `ALP` after a float codec, which ClickHouse creates but cannot insert into) and `codec_type_unsupported` (such as `T64` on `Float64` or `Delta` on `String`, through `Nullable`, `Array`, `LowCardinality`, `Tuple` and `Map`). Atoms of a raw codec that name a typed codec are checked too. `ALP` is no longer treated as a general codec, so `[ALP, ZSTD]` is accepted, and messages no longer claim that a chain must end with a general codec.
- New typed forms: `{ kind: 'Default' }`, `ZSTD` `windowLog`, `T64` `mode: 'byte' | 'bit'`, and `FPC` with optional `level` and `floatSize`. `DoubleDelta` renders an explicit `size`; ClickHouse retains it only in verbatim chains.
- `generate`, `drift` and `pull` compare codecs in the one form ClickHouse stores, so equivalent respellings (`DoubleDelta(8)` and `DoubleDelta` outside verbatim chains, `FPC(12, 8)` and `FPC` outside verbatim chains, `codec.raw('NONE')` and `{ kind: 'NONE' }`) plan nothing, a live change of the `ZSTD` window now drifts, and a raw `Delta, Default` no longer drifts forever.
- `pull` writes the codec ClickHouse stores as typed atoms: `FPC(12)` as `{ kind: 'FPC', level: 12 }` instead of `codec.raw('FPC(12)')`, `DoubleDelta` with its size when the server retains it, a bare `Delta` on a mixed-width `Tuple` or `Map` without one, and the `ZSTD` window, `T64` mode and `Default`.
- `generate` warns about each operation that sets the experimental `ALP` codec: apply it with `chkit migrate --apply --setting allow_experimental_codecs=1`.
