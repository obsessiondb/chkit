## From a definition to a reviewed migration

A schema change starts in code and produces SQL to review. This walkthrough uses TypeScript; the [Python port (alpha)](/python/overview/) provides the schema and migration workflow in Python.

<p className="home-demo-setup">Install <code>chkit</code> and <code>@chkit/core</code>, then run <code>chkit init</code> to create the project configuration. The <a href="/tutorials/first-schema/">first schema tutorial</a> covers installation, the ClickHouse connection, and each step below.</p>

<Tabs>
  <TabItem label="1. Define">

### Declare the table

Export a table from the configured schema files. Columns, engine, and ordering describe the intended ClickHouse schema.

```ts title="src/db/schema/events.ts"
import { table } from '@chkit/core'

export const events = table({
  database: 'default',
  name: 'events',
  columns: [
    { name: 'id', type: 'UInt64' },
    { name: 'event_type', type: 'String' },
    { name: 'created_at', type: 'DateTime' },
  ],
  engine: 'MergeTree()',
  primaryKey: ['created_at', 'id'],
  orderBy: ['created_at', 'id'],
})
```

The [schema reference](/schema/dsl-reference/) covers engines, keys, indexes, views, and dictionaries.

  </TabItem>
  <TabItem label="2. Review & migrate">

### Generate SQL and review the plan

Generate a migration from the definitions, inspect its SQL in `chkit/migrations/`, and preview the pending migrations before applying.

```sh title="Terminal"
bunx chkit generate --name create-events
bunx chkit migrate --json

# Apply after reviewing the generated SQL and plan.
bunx chkit migrate --apply
```

Commit the definitions, migration SQL, and metadata together. chkit records applied migrations in ClickHouse. See the [migration workflow](/guides/migration-workflow/) for review, destructive changes, and deployment.

  </TabItem>
  <TabItem label="3. Evolve">

### Add a column through another migration

Replace the table definition to add `user_id` with a default for existing rows.

```ts title="src/db/schema/events.ts"
import { table } from '@chkit/core'

export const events = table({
  database: 'default',
  name: 'events',
  columns: [
    { name: 'id', type: 'UInt64' },
    { name: 'event_type', type: 'String' },
    { name: 'created_at', type: 'DateTime' },
    { name: 'user_id', type: 'UInt64', default: 0 },
  ],
  engine: 'MergeTree()',
  primaryKey: ['created_at', 'id'],
  orderBy: ['created_at', 'id'],
})
```

```sh
bunx chkit generate --name add-user-id
bunx chkit migrate --json
bunx chkit migrate --apply
```

chkit compares the updated definition with the last snapshot and generates an `ADD COLUMN` migration. Review the SQL before applying it.

  </TabItem>
  <TabItem label="4. Verify">

### Check migration state and drift

Check whether migrations are pending, checksums have changed, or the live schema differs from the declared schema.

```sh title="Terminal / CI"
bunx chkit status
bunx chkit drift
bunx chkit check
```

Use [`chkit check`](/cli/check/) as the CI gate. Its exit code reports whether the schema and migration state satisfy the checks.

  </TabItem>
</Tabs>
